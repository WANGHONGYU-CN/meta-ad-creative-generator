# Meta 素材工厂

给 Meta 投放团队用的素材流水线工具：**建产品 → 找场景（含评分）→ 场景变量直填生图总提示词 → 生图 → 看图写文案 → 导出交付包**。

> 本项目为长期维护的生产项目。项目档案、技术决策与开发协作规范见 [CLAUDE.md](CLAUDE.md)。
> 开发在 `develop` / `feature/*` 分支进行，不直接提交 `main`。

## 架构

FastAPI + React Web 应用，数据层 **PostgreSQL**（结构化数据）+ 文件系统（图片）：

- 业务数据（产品/任务/场景/图片记录/文案/对话/场景库/提示词）全部在 PostgreSQL；
- 图片二进制仍在 `outputs/run_{id}/`，库里只存相对路径；
- 提示词（含出厂默认）也在库里，`alembic upgrade head` 即得完整可用库。

## 启动

**1. 数据库**（首次：复制 `.env.example` 为 `.env.local` 填好凭据；`~/.bashrc` 配 `DATABASE_URL`）：

```bash
cd /mnt/c/Users/yueg0/meta-creative-tool
docker compose up -d                                    # PostgreSQL 17（Docker Desktop 需开 WSL integration）
~/venvs/meta-creative-tool/bin/alembic upgrade head     # 建表 + 出厂提示词 seed（幂等）
```

**2. 应用**：

```bash
~/venvs/meta-creative-tool/bin/uvicorn server.main:app --port 8000
```

浏览器打开 **http://localhost:8000**（左侧导航五页 + 工作台分步面板）；http://localhost:8000/docs 是接口调试文档。**必须单进程**（不要加 `--workers`，进程内锁与线程池不支持多 worker）。

> 依赖 venv 放在 WSL 原生磁盘（`~/venvs/meta-creative-tool`）而不是项目目录——项目在 C 盘（9p 文件系统），venv 放这里冷启动要 35 秒+，放 WSL 侧只要 1 秒。重装依赖：`~/venvs/meta-creative-tool/bin/pip install -r requirements.txt`。

前端构建产物 `web/dist/` 已入库，pull 后无需 Node 即可使用。改前端源码（`web/src/`）后需重新构建：

```bash
cd web && npm install && npm run build   # node_modules 建议放 WSL 原生盘（符号链接），项目里已按此配置
```

## 第一次使用

1. 进「设置」页，填入 Anthropic API Key（文字环节）和 OpenAI API Key（生图），点保存 → 测试连接
2. 如需修改 AI 的行为，进「提示词」页，6 套提示词（主流程 3 套 + 分支 3 套）可在线编辑、可恢复出厂默认
3. 顶栏「新任务」→ 选择已有**产品**或就地新建产品（产品带默认品牌名/广告语言，建任务时带入）→ 进工作台按分步面板走完流程
4. 做过的素材在「历史素材」页可搜索浏览（数据实时来自数据库，无需重建索引）

## 工作流说明

| 步骤 | 做什么 | 可人工干预 |
|------|--------|-----------|
| 产品信息 | 填产品信息、品牌名称、广告语言，上传 海报风格参考图 / 品牌 Logo（均可选），选尺寸（1:1 / 4:5 / 双尺寸）、文案套数。上传过的图自动进**参考图历史库**，「从历史图选择」可勾选复用 | — |
| 投放场景 | Claude 挖掘主场景 + 细分场景（含目标用户、触发时刻、痛点/渴望、产品使用链路、五维评分），后台运行不占页面；**精简模式默认开**——每组只显示评分前 30%（已勾选恒显示） | 筛选器过滤展示；点卡片多选；「详情」看完整字段；对话框让 AI 修改场景结果 |
| 生成图片 | 勾选场景一键生图：场景变量 + 品牌名/广告语言/比例 **直接填入「生图总提示词」模板**，gpt-image 并行出图（带风格参考图 / Logo），海报文字由生图模型自行撰写 | 每张图提示词可编辑/AI 修改后单张重生成；对话改图**后台并发**（多张同时改）；每张图保留最近 10 个历史版本，任意回跳 |
| 文案与导出 | Claude 看图写多套标题文案并绑定；导出交付包 | 文案表格可编辑；对话框让 AI 整批修改 |

每一处「对话框」都是持续对话：AI 拿**当前结果 + 你的修改意见 + 之前几轮意见**去改，可以一直聊到满意为止。

## 场景库

- 挖掘出的场景**自动汇总进「场景库」页**，按产品累积；同一产品再次挖掘时，库里已有场景自动作为排除清单传给 AI，避免重复。
- 勾选场景创建生图任务时，**自动继承同产品最近任务的风格参考图、Logo、品牌名称和广告语言**；任务不带参考图时生图前会显式警告「将纯文生图」。
- 可按 关键词 / 产品 / 主场景 / 总分区间 / 出图状态 / 投放状态 筛选排序；**已出图**自动打标、**投放中**人工勾选；删除只删库记录。

## 多任务与后台运行

- **任务切换**：顶栏在任务间切换，每个任务的全部状态自动保存在数据库，切走再切回不丢。
- **后台运行**：挖场景 / 生图 / 批量文案 提交后即后台运行，期间可切到别的任务干活；失败单项可「补齐/重试」。
- **图片修改并发**：对话改图可多张同时进行，只有被修改的图卡片显示「修改中」；与生图/文案管线互斥。
- **图片版本历史**：每张图保留最近 10 版，任意回跳；回到旧版后再修改会丢弃后面的版本。
- 注意「后台」指不占页面；关掉服务进程任务会停，已完成的部分都已入库。

## 尺寸说明

- 4:5：gpt-image-2 系原生 1024×1280 直出；gpt-image-1 等按 1024×1536 生成后居中裁切 1024×1280。1:1 为原生 1024×1024。
- **双尺寸**：先出 4:5 母版，再用「尺寸改版」提示词把成品图改成 1:1，内容与母版一致（AI 重绘，细节可能微小差异）。母版重生成/被修改/换版本后，1:1 自动待重做。

## 文件与数据说明

- **PostgreSQL（Docker 卷）**：产品、任务、场景、图片记录、文案、对话历史、场景库、提示词。备份用 `docker exec meta-creative-db pg_dump -U meta meta_creative > backup.sql`
- `config.json`：API key 与模型配置（仅存本机，已 gitignore）；`DATABASE_URL` 走环境变量
- `outputs/run_{id}/`：任务的图片与导出物
  - `images/` 所有图片（`.hist/` 为版本历史），文件名 = `主场景_细分场景_尺寸.png`
  - 导出后生成 `交付表.xlsx` 与 `交付包.zip`（zip 内含图片 + manifest.json + 交付表）
- `data/ref_assets/`：全局参考图库文件（元数据在库里）
- `logs/app.log`：运行日志（已 gitignore），按天滚动保留 14 天；批量任务有失败时来这里看完整原因
